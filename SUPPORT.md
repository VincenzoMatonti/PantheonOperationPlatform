# Pantheon Support

## Overview

Pantheon is an open source project developed and maintained by **Vincenzo Matonti**.

Community members are welcome to ask questions, share knowledge, and discuss how Pantheon can be used and extended.

This document explains where to seek help and how to report different types of problems.

## Community Support

For questions, discussions, and general help with Pantheon, use **GitHub Discussions**.

GitHub Discussions can be used for:

* Questions about using Pantheon
* General technical discussions
* Sharing experiences and solutions
* Discussing ideas
* Exploring possible project directions
* Asking for guidance before opening an Issue

## Bug Reports

If you have identified a reproducible problem with Pantheon, create a **Bug Report** through the GitHub Issue templates.

Before opening a new issue:

* Check existing Issues.
* Check existing Discussions.
* Make sure the problem is reproducible.
* Provide the relevant environment and version information.
* Include relevant logs or error messages when possible.

## Feature Requests

If you would like Pantheon to provide a new capability or improvement, use the **Feature Request** Issue template.

Feature requests should describe:

* The problem or use case.
* The proposed capability.
* Possible alternatives or workarounds.
* The expected impact.

## Technical Proposals

For architectural, infrastructure, or other significant technical changes, use the **Technical Proposal** Issue template.

Technical proposals are intended for changes that require technical discussion and evaluation before implementation.

## Security Vulnerabilities

Do not report security vulnerabilities through GitHub Issues or public Discussions.

Security vulnerabilities should be reported privately through **GitHub Security Advisories**.

See [`SECURITY.md`](SECURITY.md) for the project's security policy and reporting guidelines.

## Commercial and Professional Support

Pantheon is an open source project.

The project may provide official commercial services in the future, including professional support, consulting, integrations, managed services, cloud services, or enterprise offerings.

Any official commercial services will be announced through the project's official channels.

Until such services are officially established, GitHub Discussions should be used for community support.

## Before Asking for Help

When requesting help, provide enough information to understand the situation.

Depending on the problem, this may include:

* Pantheon version or commit
* Operating system
* .NET version
* Docker version
* Relevant component
* Configuration details
* Error messages
* Logs
* Steps to reproduce the problem

Avoid sharing passwords, credentials, access tokens, private keys, secrets, or other sensitive information.
